🧭 ModernBERT Lab

長文をそのまま読む ModernBERT で、公開情報を見極める

トピックを入れるとブラウザが検索エンジンを巡回して記事を集め、端末内の日本語 ModernBERT（最大 8,192 トークンを分割せずに読む）で、矛盾・偏り・一次情報・時間的ずれを検証し、足りない情報と反対意見を洗い出し、比較表・要約・Q&Aに構造化する。LLM を使わず、サーバも API キーも不要。

この研究で確かめること

  1. 長文を一括処理すると精度が上がるか — 同じ記事・同じ問いを「8,192 トークン一括」と「512 トークンに分割して最大値」で処理し、判定と時間を比べる（「長文 vs 分割」タブ）
  2. 不足している情報・反対視点を自律的に見つけられるか — 12 種類の問い（誰が・いつ・根拠・反対意見…）が集めた記事で答えられているかをリランカーで判定し、答えのない問いに検索式を提案する（「ギャップ・対立」タブ）
  3. 長文から人が見やすい構造化データに直接変換できるか — 記事群を「メリット／デメリット／費用／時期／根拠」などの軸で表にし、根拠つきで要約する（「構造化」タブ）

長文一括 vs 分割 — 仮説 1 の実験。同じ文書・同じ問いを、8,192 トークン一括と 512 トークン分割で処理して比べる

一括：文書を先頭から最大 8,192 トークン入力（ModernBERT 系のみ）。分割：文を境に分け、各チャンクのスコアの最大値を採用（従来の BERT 系と同じやり方）。

流れ

トピック／URL→Dorks で検索エンジン巡回→本文抽出→信頼性採点（出所・内容・裏取り・時間）→コーパスとして履歴に保存→検証／ギャップ／構造化（埋め込み・含意・リランカー）

各機能で何をしているか

矛盾・整合各記事の要旨（冒頭の命題）を他記事の段落と突き合わせ、含意モデルで 一致／矛盾／無関係 を判定して行列にする 偏り・客観性埋め込みゼロショット（客観／主観／感情／宣伝）＋ 含意ゼロショット（「この文章は客観的な事実を報告している」など）＋ 語彙（煽り語・推量表現・宣伝語の密度）を合成し 0〜100 一次情報出所の種別（公的・報道・ブログ…）＋ 引用・伝聞表現と発表元表現の数 ＋ 含意ゼロショット（一次／二次） 時間的矛盾年月・和暦・数値＋単位を抽出。本文中の最新年が古いのに「現在」と書く／公開日より新しい年／同じ項目で記事間の数値が食い違う、を警告 ナレッジギャップ12 種類の問いテンプレートをトピックに当て、埋め込みで候補段落を絞り、リランカーの関連度がしきい値未満なら「未回答」。未回答の問いには検索式を提案 対立視点段落を 賛成／反対／中立 にゼロショット分類し、反対・課題の段落を列挙。加えて記事間の命題ペアで含意モデルが「矛盾」としたものを列挙 意味差分文を埋め込みで対応づけ、変わった対を含意モデルで双方向に判定：両方向含意＝言い換え、片方向＝情報の増減、矛盾＝意味の反転 比較表軸ごとに「軸は何か」を問いとして各記事の文をリランカーで採点し、最良の文をセルに入れる 要約段落の埋め込みの重心との類似（出所の重みつき）を関連度とし、MMR で冗長を避けて選ぶ。抽出型なので出典が必ずつく Q&A埋め込みで候補 → リランカーで関連度 → 上位段落を根拠として提示。質問が命題なら含意も判定

信頼性スコア R（0–100）

R = 100 × ( wsrc·ssrc + wcon·scon + wcor·scor + wtime·stime )

ssrc 出所ドメイン種別の基礎点（公的 1.0 … SNS 0.3）＋ HTTPS ＋ ドメイン年齢（Wayback 最古）＋ Wikipedia 出典回数 ＋ 著者・日付scon 内容0.35·長さ ＋ 0.40·具体性（数値・日付・引用・固有名詞）＋ 0.25 ＋ 文体（煽り −0.3、報告 +0.2、意見 −0.1、宣伝 −0.2）scor 裏取り要旨を他ドメインの段落が含意する重み付き件数 S（同趣旨の中立は部分点）、矛盾 C：0.15 + 0.85·(1−e−S/2) − 0.6·(1−e−C/2)stime 時間0.2 + 0.8·0.5経過日数/30（日付なし 0.4）
