🧭 情報たしかめラボ

Web 情報の信頼性を、手順で検証する

SNS・ニュース・動画で見た情報について、検証対象を明示し、公開情報を集めて照合し、根拠を示して判定するというファクトチェックの手順を、ブラウザだけで実行できます。収集した記事と主張の照合は端末内の日本語言語モデルが行い、判定の下書きと根拠つきの検証記録を出力します。最終的な判定は利用者が根拠を読んで行います。

1検証対象を明示する「誰が・何を・いつ」が入った、客観的に確かめられる一文にする。意見や予測は対象外
2公開情報を集める検索演算子（site:go.jp など）で一次情報・報道・検証記事を探す。画像は逆画像検索
3照合する集めた記事が主張と一致するか・矛盾するか、発信元の種類と日付とともに読む
4判定し、過程を記録する5 段階で判定し、検索式・出典 URL・理由を残す。誰でも同じ手順で再現できるように

ファクトチェックの手順を、端末内の ModernBERT で支援する

検証対象を明示 → 検証過程を公開 → 判定というファクトチェックの基本手順（日本ファクトチェックセンターの講座に準拠）に沿って、主張を入れるとブラウザが高度な検索で公開情報を集め、端末内の日本語 ModernBERT（最大 8,192 トークンを分割せずに読む）で主張と各記事の含意・矛盾を照合し、5 段階の判定の下書きと根拠リンクつきの検証記事を作る。画像・動画の逆検索、公開データ、ジオロケーションなどの外部ツールもここから開ける。LLM を使わず、サーバも API キーも不要。

初めて使う方へ

  • アカウント登録・ログインは不要。入力した内容と結果はあなたの端末（ブラウザ）だけに保存され、作者を含め誰にも送られない
  • 初回はモデル（約 108 MB）を端末にダウンロードする（Wi-Fi 推奨）。検索・本文取得にはインターネット接続が必要
  • 検索・本文取得は無料の公開経路を使うため、混雑時は遅くなることがある。結果は届いた順に表示される
  • 機械の判定は下書き。必ず根拠リンクを開いて一次情報を確かめる。人物の特定や非公開情報の取得には使えない
  • 履歴を残したくないときは右上の「🔒」でプライベートモードに。結果はタブを閉じると消える
  • 別の端末に履歴を移すには「設定」→ JSON で書き出し → もう一方で読み込む

最近の作業

この研究で確かめること

  1. RQ1 独自モデルの効果 — ファクトチェック由来のデータ（JAD-AFC）で微調整した FactCheck-BERT は、汎用 NLI だけのモデルや海外の多言語 NLI より、主張と証拠の照合に強いか。結果：5 分割交差検証で正解率 0.834±0.029（汎用 NLI だけ 0.32、多言語 NLI 0.22、学習なし 0.49）。さらに「ファクトチェック」タブの一括検証で、検索から判定までの通しでも差が残るかを測る
  2. RQ2 検索の改善 — 信頼性スコアと関連度で並べ替えると、検索エンジンの元の順位より上位の質が上がるか（Precision@k・MRR・nDCG）
  3. RQ3 端末内実行 — 30M クラスのモデルを int8 でスマートフォンのブラウザで動かし、実用的な時間で検証できるか（モデル合計 100 MB 以下、1 記事 5 秒以内）

流れ

主張→6 種類の検索式 × 検索エンジン→読む前の優先順位（主張の語・情報源の種類・複数式での出現・同一サイト 2 件まで・SNS は後回し）→本文抽出（3 件ずつ並列）→信頼性採点（出所・内容・裏取り・時間）→埋め込みで候補段落を絞る→FactCheck-BERT（含意）で 一致／矛盾／無関係→5 段階の判定の下書き・検証記録

端末内モデルは 3 つ：埋め込み（段落検索・クラスタ・客観性。既定 ruri-v3-30m）、含意（主張 × 段落の一致／矛盾。既定 nli-ja-30m）、関連度（「分析」タブの問い合わせ用。必要なときだけ読み込む）。いずれも ModernBERT-Ja 30M を土台にした ONNX int8（各 36 MB）。「ファクトチェック」で使うのは埋め込みと含意の 2 つ。「モデル」タブで学習前の土台や海外モデルに入れ替えて同じ画面で比べられる。

各機能で何をしているか — 「ファクトチェック」の照合と、「分析」タブの各機能

主張の照合（ファクトチェック）集めた記事を段落に分け、埋め込みの類似度と「主張の語・数値が含まれるか」で関係のある段落だけを選び（ここで無関係を除く）、含意モデルで 一致か矛盾か を判定（確率の差が小さい段落は数えない。主張の否定形でも同じ答えになる段落も外す）。出所の重みをかけた一致・矛盾の合計と情報源の数（2 ドメイン以上）から 一致／矛盾／混在／根拠不足 を決め、JFC 式の 5 段階（正確／ほぼ正確／根拠不明／不正確／誤り）の下書きにする。判定は「公開情報との整合」であって真偽の証明ではない 矛盾・整合各記事の要旨（冒頭の命題）を他記事の段落と突き合わせ、含意モデルで 一致／矛盾／無関係 を判定して行列にする 偏り・客観性埋め込みゼロショット（客観／主観／感情／宣伝）＋ 含意ゼロショット（「この文章は客観的な事実を報告している」など）＋ 語彙（煽り語・推量表現・宣伝語の密度）を合成し 0〜100 一次情報出所の種別（公的・報道・ブログ…）＋ 引用・伝聞表現と発表元表現の数 ＋ 含意ゼロショット（一次／二次） 時間的矛盾年月・和暦・数値＋単位を抽出。本文中の最新年が古いのに「現在」と書く／公開日より新しい年／同じ項目で記事間の数値が食い違う、を警告 ナレッジギャップ12 種類の問いテンプレートをトピックに当て、埋め込みで候補段落を絞り、リランカーの関連度がしきい値未満なら「未回答」。未回答の問いには検索式を提案 対立視点段落を 賛成／反対／中立 にゼロショット分類し、反対・課題の段落を列挙。加えて記事間の命題ペアで含意モデルが「矛盾」としたものを列挙 意味差分文を埋め込みで対応づけ、変わった対を含意モデルで双方向に判定：両方向含意＝言い換え、片方向＝情報の増減、矛盾＝意味の反転 比較表軸ごとに「軸は何か」を問いとして各記事の文をリランカーで採点し、最良の文をセルに入れる 要約段落の埋め込みの重心との類似（出所の重みつき）を関連度とし、MMR で冗長を避けて選ぶ。抽出型なので出典が必ずつく Q&A埋め込みで候補 → リランカーで関連度 → 上位段落を根拠として提示。質問が命題なら含意も判定

判定でできること・できないこと

できる「〇〇の△△は ◇◇ である」「〇〇は □年□月に △△ した」のような、固有名詞＋事実＋（数値・日付）の 1 文。数値つきの主張は、同じ語と単位を含む文の数値を規則で比べる（一致／不一致）。数値の無い主張は、主張の語を含む 1〜2 文を含意モデルで「一致か矛盾か」だけ判定し、確率の差が小さい文・否定形でも同じ答えになる文は数えない。2 つ以上の独立したドメインで揃ったときだけ結論を出す できない評価（危険・良い）、意見、予測、伝聞（〜らしい）、複数の文、主語の無い文 → 入力の時点で「判定留保」。段落全体の読解、表や画像の中の数値、ページ自体が正しいかの判断（信頼性は出所の種別と独立ドメイン数で代用）。公開情報に該当する記述が無ければ「根拠不足」で止まる（収集の限界と判定の限界は通し検証で切り分ける） 判定の意味「一致する根拠あり／矛盾する根拠あり」は、集めた公開ページの記述との整合であって、真偽の証明ではない。5 段階の下書き（正確／誤り…）も同じ意味で読む

信頼性スコア R（0–100）

R = 100 × ( wsrc·ssrc + wcon·scon + wcor·scor + wtime·stime )

ssrc 出所ドメイン種別の基礎点（公的 1.0 … SNS 0.3）＋ HTTPS ＋ ドメイン年齢（Wayback 最古）＋ Wikipedia 出典回数 ＋ 著者・日付scon 内容0.35·長さ ＋ 0.40·具体性（数値・日付・引用・固有名詞）＋ 0.25 ＋ 文体（煽り −0.3、報告 +0.2、意見 −0.1、宣伝 −0.2）scor 裏取り要旨を他ドメインの段落が含意する重み付き件数 S（同趣旨の中立は部分点）、矛盾 C：0.15 + 0.85·(1−e−S/2) − 0.6·(1−e−C/2)stime 時間0.2 + 0.8·0.5経過日数/30（日付なし 0.4）
