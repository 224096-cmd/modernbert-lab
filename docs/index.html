流れ

トピック／主張／URL→Dorks 生成→DDG・Bing・Yahoo・Google ニュース・はてな・Wikipedia…→本文抽出（trafilatura / r.jina.ai）→ModernBERT：埋め込み（Ruri-v3-30m）・含意（JNLI 微調整 30M）→出所・内容・裏取り・時間の 4 軸で採点→docs/data/*.json → このページ

信頼性スコア R（0–100）

R = 100 × ( wsrc·ssrc + wcon·scon + wcor·scor + wtime·stime )

ssrc 出所ドメイン種別の基礎点（公的 1.0 … SNS 0.3）＋ HTTPS ＋ ドメイン年齢（Wayback 最古） ＋ Wikipedia 出典回数 ＋ 著者・日付の有無 scon 内容0.35·長さ(本文/800字) ＋ 0.40·具体性(数値・日付・引用・固有名詞) ＋ 0.25 ＋ 文体（ゼロショット：煽り −0.3、報告 +0.2、意見 −0.1、宣伝 −0.2） scor 裏取り要旨（冒頭の 1 文）を、他ドメインの段落が含意する重み付き件数 S（含意に届かない同趣旨の段落は 0.5×類似度の余裕×P(中立) の部分点）、矛盾 C：0.15 + 0.85·(1−e−S/2) − 0.6·(1−e−C/2)。含意判定は JNLI 微調整モデル、候補は Ruri 埋め込みの cos 上位 k stime 時間0.2 + 0.8·0.5経過日数/半減期（日付なしは 0.4） 評価A ≥ 75、B ≥ 60、C ≥ 45、D

主張の検証

主張を「検索クエリ: 」で埋め込み → 段落（「検索文書: 」）の cos 上位 k → JNLI(前提=段落, 仮説=主張) → 支持 = Σ 出所重み×P(含意)、反証 = Σ 出所重み×P(矛盾) → 支持 ≥ 1.5 かつ反証が支持の 60% 未満なら「支持」、逆なら「否定」、両方あれば「食い違い」、どちらも小さければ「根拠不足」。

Dorks テンプレート

既存モデルの比較 — 同じデータ（JSTS・JNLI）と同じ CPU で測る。土台を選んで微調整すると独自モデルになる

実行：python -m mbo.bench --roles embed,nli --max-mb 600（Actions の bench ワークフローでも可）。指標：JSTS Spearman（文類似）、JNLI cos 差（含意対と矛盾対の cos の差）、JNLI 正解率・含意再現率・ECE（較正）、1 件あたり CPU 遅延、パラメータ数、配布サイズ。

微調整して独自モデルを作る

  1. 上の表から土台（role=base）を選ぶ。小さい順に modernbert-ja-30m → 70m → 130m、比較用に bert-base-japanese-v3 / line-distilbert / deberta-v2
  2. python -m mbo.train_nli --base sbintuitions/modernbert-ja-70m --n 20073 --epochs 3 --balance --out models/nli-ja-70m-torch（Colab: notebooks/train_nli.ipynb、Actions: train ワークフロー）
  3. python -m mbo.export_onnx --nli models/nli-ja-70m-torch --out models/nli-ja-70m → python -m mbo.calibrate --model models/nli-ja-70m
  4. python -m mbo.bench --local models/nli-ja-70m-torch --names nli-ja-70m --role nli で表に載せる
  5. 「設定」でブラウザ用の含意モデルに nli-ja-70m を指定すると、このサイトの判定がそのモデルに切り替わる（Actions 側は MBO_NLI 環境変数）

GitHub Actions の手動実行
リポジトリの Actions → collect → Run workflow で、トピック・主張・ドメインを 1 つ指定して即時実行できる。結果は数分後にこのページの「自動収集」に出る（Pages の更新込みで 3〜5 分）。

 
アプリとして入れる
Android/PC Chrome：アドレスバーの「インストール」。iPhone：共有 → ホーム画面に追加。収集済みデータとモデルは端末に保存され、オフラインでも閲覧・判定できる。
